# Optional eight-section specification profile

Use only when the project adopts this profile; otherwise keep its existing template. Replace guidance with actual content. This is a Northstar profile, not the universal GitHub Spec Kit schema. Record the governing constitution/template version and link the project's canonical goal; keep one spec.

## 1. Intent and evidence

User, workflow, intended value, environment and source/version links. Cite material claims; distinguish an owner's requested behavior from externally verified facts.

## 2. Scope and user journeys

Prioritized complete journeys, Given/When/Then acceptance cases, boundaries and excluded work. Preserve required failure/recovery behavior.

## 3. Functional requirements

- **FR-001:** <observable required behavior; source citation; linked SC/check>

Give every FR a real source, including the owner's request where appropriate. Use stable IDs across tasks and checks.

## 4. Key entities

- **KE-001:** <entity, relevant relationships/invariants; FR/source links>

Write not applicable with a reason if the workflow has no meaningful entities.

## 5. Success criteria

- **SC-001:** <observable outcome, inputs/environment, threshold, judging method; FR links>

Require independent checks of actual output and relevant failure boundaries. Implementation evidence is added only after execution.

## 6. Assumptions and constraints

- **A-001:** <assumption, evidence/uncertainty, validation owner/check and consequence if false>

Include actual privacy, resource and authority constraints with citations to governing rules. Do not invent constitution articles.

## 7. Delivery and verification links

Link existing plan, tasks and review record. Map each FR/SC to an owner, task, proposed check, and later observed evidence/revision. Link structural, evidence/privacy and adversarial pass outcomes; distinguish spec readiness from implementation readiness.

## 8. Open questions and decisions

- **Q-001:** <unresolved decision/finding; affected FR/SC; owner, next check/unblock condition and status>

Resolved entries retain the decision and evidence. Required behavior and material findings stay blocking until resolved and independently rechecked; optional later questions need explicit scope disposition.
