# Examples

- **New product idea with unclear customer and revenue model:** Resolve the user and job enough to choose a bounded validation goal. Research evidence and label assumptions; a working MVP may be the cheapest way to test them. Define its decision threshold and production path without treating implementation as proof of demand.
- **MVP of a local CSV viewer:** Deliver file selection, parsing, and a readable table; check malformed input and relevant file-handling risks. If accounts, billing, and cloud sync are outside the requested scope, put them in later increments. A working local workflow does not establish a safe public upload service.
- **A new chat resumes an accepted import workflow:** Inspect the existing artifact and the check's revision/environment. Continue the next unmet criterion; do not rebuild import or rerun unchanged checks just because context changed. If a parser dependency changed, recheck affected parsing and integration behavior.
- **Reviewer asks for optional export themes after MVP criteria pass:** Record the enhancement for later and deliver the current slice. If the reviewer instead finds corrupt exported data, repair it and recheck affected behavior before acceptance.
- **Two repair attempts produce the same failure with no new evidence:** Follow [stall recovery](../SKILL.md#recover-from-a-stall): preserve the current diff, isolate the smallest failing case, and test a distinguishing hypothesis within a bounded window. Carry the checkpoint and rejected paths across agent/context changes. If still blocked, name the unblock condition and continue independent work.
- **One provider now, a credible second provider later:** Keep core rules independent of provider-specific response shapes through a small boundary where needed. Implement and verify the current provider only; inspect how the next would fit. Do not build a plugin platform or claim the second provider already works.
- **Known goal, unfamiliar SDK:** `AUTO` for bounded reversible investigation and implementation. The AI reads authoritative docs, builds the smallest integrated slice, and verifies it; it does not ask the user to choose an SDK without first comparing options.
- **Complex local refactor with tests:** `AUTO` when bounded and reversible, even if implementation complexity is high. The AI researches dependencies and verifies behavior.
- **Production deployment with a known rollback:** `GUARD`. Prepare and verify the release; deploy only within existing explicit authorization for this action and target. Ask if authority is missing or consequences materially changed. Rollback availability alone is not permission.
- **Privacy-impacting architecture with unresolved product tradeoffs:** `CHALLENGE`. Present evidence, viable alternatives, consequences, and a recommendation for human decision.
- **Brand or positioning choice:** `COCREATE` when the product owner owns the taste or positioning call; bring evidence and options rather than asking an open-ended question.
- **Writing a personal apology where authenticity is the point:** `HUMAN_ONLY`.
