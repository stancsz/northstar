# Examples

- **New product idea with unclear customer and revenue model:** Resolve the user and job enough to choose a bounded validation goal. Research evidence and label assumptions; a working MVP may be the cheapest way to test them. Define its decision threshold and production path without treating implementation as proof of demand.
- **MVP of a local CSV viewer:** Deliver file selection, parsing, and a readable table; check malformed input and relevant file-handling risks. If accounts, billing, and cloud sync are outside the requested scope, put them in later increments. A working local workflow does not establish a safe public upload service.
- **A new chat resumes an accepted import workflow:** Inspect the existing artifact and the check's revision/environment. Continue the next unmet criterion; do not rebuild import or rerun unchanged checks just because context changed. If a parser dependency changed, recheck affected parsing and integration behavior.
- **Reviewer asks for optional export themes after MVP criteria pass:** Record the enhancement for later and deliver the current slice. If the reviewer instead finds corrupt exported data, repair it and recheck affected behavior before acceptance.
- **Two repair attempts produce the same failure with no new evidence:** Preserve the diff and use one bounded [recovery window](../SKILL.md#recover-from-a-stall). If it also fails, [decide and act](../SKILL.md#decide-after-exhausted-recovery): choose one supported alternative, resolve a dependency, or stop that route with its unblock condition; execute independent authorized work. Carry attempts and any alternative trial across agent/context changes.
- **A wrapper fails repeatedly but its supported local parser meets the same contract:** After exhausted recovery, choose the parser when evidence shows it avoids the failed wrapper path. Run a bounded trial against the original inputs and acceptance; do not ask the user to choose an implementation. If that alternative also fails, stop and disposition the blocker rather than trying endless libraries.
- **A missing customer export prevents the promised report:** Preserve the missing-data finding; do not invent a total. State the exact needed input, advance independent assigned work if available, and otherwise hand off the honest blocker. Autonomy does not make missing evidence available.
- **A shared-interface owner does not answer:** Keep the existing contract and make any compatible local repair. Bound the coordination wait and route a necessary interface decision directly to its responsible manager through authorized channels. Do not edit the absent owner's files or treat silence as consent.
- **One provider now, a credible second provider later:** Keep core rules independent of provider-specific response shapes through a small boundary where needed. Implement and verify the current provider only; inspect how the next would fit. Do not build a plugin platform or claim the second provider already works.
- **Known goal, unfamiliar SDK:** Investigate authoritative docs and implement the smallest complete slice within the mandate. Unfamiliarity is work for the agent, not a choice to return to the owner.
- **Complex local refactor with tests:** The commander assigns bounded implementation and independent review, then acts on the evidence. Complexity alone creates no extra approval stage.
- **Production deployment with a known rollback:** If the standing grant covers that target and action, verify and execute without reapproval; the commander may subdelegate execution inside those limits. An uncovered target needs its actual authority owner, not an assumed expansion from a connected account.
- **Privacy-impacting architecture with unresolved product tradeoffs:** Inspect the concrete data effects and constraints; the commander decides the in-mandate tradeoff with evidence and an appropriate check. Escalate only an actual retained choice or a change beyond the grant.
- **Brand or positioning choice:** When delegated, product/experience agents supply evidence and the commander decides; retain separate taste review of authored work. Ask the owner only for a choice they explicitly retained or indispensable personal context.
- **Writing a personal apology where authenticity is the point:** Help draft from the person's actual intent; do not invent personal feelings or consent. Use any actual communication authorization rather than treating drafted text as permission to send.
- **Configured Notion, delegated project operation:** Update the assigned project pages, task states and learning records directly through the working connection. No page-by-page permission question. If a tool rejects access, diagnose the specific failure and continue independent work; ask only for an indispensable human-held fix.
