# 自主完成契约

人的注意力和介入时间是本系统优先减少的成本。目标不是不断运行进程，而是在授权范围内自主完成目标并提供验收证据。

人通过 MCP 查看报告、设置下一条 Goal 或明确调整方向。Agent 在当前 Goal 内自主执行和恢复；完成后提交报告并等待人的下一条指令，不自行发明后续 Goal。减少的是执行救火，不是取消人的目标决定权。

- 主 Agent 自己选择模板、组织临时 A2A 团队、决定下一项任务；不存在强制固定的交付/监督流水线。
- 普通错误留在任务内修复，原生重试有恢复空间；最终任务失败由主 Agent 根据产物和独立监督意见继续修复，不把整个目标卡死。
- 会话、任务 ID、候选版本、验收及恢复过程持久化。进程退出后自动接回同一目标；确认旧进程死亡后创建延续任务，不重复执行未知状态的写任务。
- 监督先给出可执行纠偏，让 Agent 自己复位；低风险可逆修复不交回人工审批。不会因为固定时间、轮数、费用或少量错误而强制停止。
- 完成必须通过独立角色的真实候选审查和原始检查；测试失败、版本过期、证据缺失会触发修复，不能被包装成完成。
- 只有真正缺少授权、凭据、外部材料或用户必须决定的不可逆事项才请求人工，并说明已有证据及具体缺失项。

验收标准：一次性给出目标后，不由人或上层聊天逐步救场；Agent 自己组队、实施、验收、应对注入故障并完成。无法做到时，明确保留未满足项，不用“已启动”或手动救通替代。
