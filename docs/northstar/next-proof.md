# Northstar's next proof

Proposed direction from the [2026-09-29 dogfood review](../evals/dogfood-review.md). This sharpens the existing [owner direction](README.md); it does not replace its project/business scope, five-skill package or required ceremonies. The review is complete; the pilot below has not run.

Subsequent owner requirement: [healthy functional roles and independent acceptance](../goal/healthy-roles/GOAL.md) changes the package before any pilot. Identify the resulting source snapshot when freezing a future comparison; the earlier review fingerprint is historical. In a comparison, maintain the owner's independent-review requirement in both arms rather than weakening the baseline to manufacture a benefit.

## North Star

**Help an owner get more real work accepted to their standards, with less total effort and less need to rescue the agents.**

Use capable lower-cost agents for bounded execution and stronger judgment where the decision warrants it. Quality and authority remain constraints. Count coordination, consultation, review, retries and repair; shifting work to the owner or an expensive commander is not an efficiency gain.

The current constraint is evidence of practical usefulness. Local packaging, offline checks and narrow exercises establish specific capabilities. They do not establish better real-task outcomes, economical operation, repeat use or sustained business performance. More organizational guidance is not the next priority unless an observed failure calls for it.

## Ordered next work

1. **Test the current package on a small, frozen, matched software cohort.** Start with three previously unseen real tasks: one routine change, one multi-part change where delegation could help, and one actual failure/integration problem. These are diagnostic cases, not a statistically representative benchmark. Identify the source snapshot, task criteria, baseline and accounting boundary before execution. Do not reuse the familiar CSV fixture as held-out evidence.
2. **Simplify the friction actually observed.** If agents or newcomers miss the simple route or load unnecessary process, surface the existing routine path and companion triggers. Preserve mandatory checkpoint learning and relevant QA. Compare a separately identified revision on fresh tasks; do not silently change a running comparison. Consolidate duplicated explanations only where role-specific obligations remain clear. If no material friction is observed, skip this change.
3. **Validate business operations and experience reuse separately.** Use an actual eligible operating workflow with an accountable operator, commitments, observable outcomes and a defined review period. Check a later period/handoff for reuse of a valid lesson and avoidance of a rejected path. Keep promises, quality and authority fixed. Software results and a synthetic scheduling example cannot establish business value. After useful delivery, voluntary reuse on another eligible task supplies a separate adoption signal.

The orchestrator owns this sequence and selection of eligible work. A supervisor owns each future pilot's frozen criteria and accounting; an independent reviewer judges acceptance. These are responsibilities for the next assignment, not a claim that another team or scheduled run already exists. Reorder cohorts if available work or an owner priority makes a business question the more consequential, measurable first test.

## Smallest credible first comparison

Use the same task request, isolated starting snapshot, permissions and capable lower-cost worker model/reasoning configuration in each arm. Name the baseline: the current direct agent workflow without the Northstar bundle. Preserve all other repository requirements; do not cripple its tools or hide context to create a weak control. Record any unavoidable setup differences.

Use fresh contexts, prevent access to the other arm's solution/review, and counterbalance run order. Freeze the acceptance rubric before either run and give the evaluator the artifacts without revealing the arm where practical. The treatment may invoke coordination or advice according to the skill's real triggers; count every such action. Record strong-model takeover as rescue, not worker completion. Include the commander's effort in both arms. If the host cannot isolate Northstar from a nominal control, do not label it a no-Northstar comparison.

Report each case and these measures separately; no blended score:

| Measure | Evidence needed |
| --- | --- |
| Accepted useful outcome | Predeclared criteria, actual artifact/workflow inspection, residual defects and severity; include failures in the denominator |
| Time to acceptance | Start through review and repair; identify timeouts, caps and still-unaccepted work |
| Full model effort | Actual roles/models, tokens and billed cost where exposed; include commander, workers, reviewers, advice, failed attempts and rescue |
| Owner burden | Actual interventions and time spent clarifying, correcting or taking over; unavailable time stays unknown |
| Learning transfer | A later action uses an applicable lesson or avoids a recorded failure, with evidence and a reopening condition |

Fix a reasonable per-case resource boundary before running, including review and repair. Apply unchanged recovery history; no new trial window from a reassignment. Do not turn missing usage into a zero or infer tokens from word counts. If billing is unavailable, report observed usage/effort without a monetary-savings claim. An operator watching an agent is not a measured end-user study.

**Decision rule:** any material acceptance or authority failure blocks an efficiency conclusion for that case. More accepted cases without a material quality regression warrants another bounded cohort; equal acceptance with lower fully accounted effort is a directional efficiency signal. Equal acceptance with greater effort points to targeted simplification. Mixed results or missing comparable data remain inconclusive for that claim. Record unsuccessful work and its cost; a tiny positive pilot does not justify general superiority or a percentage-savings promise.

Before broadening claims, repeat on fresh tasks and then the separate business cohort. No new reporting framework, commercial rollout, live service changes or external contact is part of this review.

## Carry-forward learning

Keep independent first observations, then one shared evidence exchange and an accountable decision. In this review the two reviewers changed positions in opposite directions; the chair used their final reasons rather than assuming consensus from earlier reports. Product's preference for a clearer first-use route remains a recorded alternative. Reopen it when actual first-use evidence shows that the current path is missed, or when it causes required checks to be omitted. Retrieve the [decision and limits](../evals/dogfood-review.md#decision-exchange) before assigning the pilot.
