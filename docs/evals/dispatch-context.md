# Dispatch context guidance evaluation

Goal: [Clear, economical subagent dispatch context](../goal/dispatch-context/GOAL.md). The owner reported agent drift and wasted tokens but supplied no failed dispatch transcript. We evaluated the wording with native-agent scenarios and the requested Codex CLI and Claude Code CLI routes.

## Guidance and independent review

The Codex Advisor council recommended refining the existing task brief with must-know facts, next action, acceptance and authority limits; it advised against arbitrary length caps or mandatory acknowledgment turns. An independent scenario review covered clear single-step work, ambiguous multi-step work, missing inputs and unrelated history. It found no material wording defect. See the [implementation report](../reports/dispatch-context/implementation.md) and [review](../reports/dispatch-context/review.md).

Codex CLI control and treatment both drifted into tool-wrapper troubleshooting and produced no task result, though their low-level tool failures differed. Since neither condition completed, the Codex CLI runs provide no comparative evidence. The task attempts were stopped after repeated drift; their token totals remain unknown.

## Conclusion

The revised brief has a limited positive signal: in the matched Claude CLI replication the treatment completed while control did not, and the native inventory pair required fewer source reads under treatment without a correctness regression. The missing-input native trials remained correct in both conditions. Keep the wording change, but claim neither general drift prevention nor measured total token savings. Codex CLI remains unresolved and requires a separate diagnosis of its tool-wrapper path before it can validate this guidance.

Follow-up evidence separates infrastructure competence from task performance. The parent verified the Codex route once (`http://localhost:4000/v1`, profile `subroute-subagents`, alias `default`); one bounded Codex implementation edit succeeded. Claude's unique-response route smoke succeeded despite a nonblocking SDK title-query diagnostic. A separate Claude Read probe returned a prompt-omitted file token through actual `tool_use`/`tool_result` and final response, but cost a reported 20,190 input / 1,302 output / 39,552 cache-read tokens ($0.153276) over 3 turns / 24.75 seconds and unnecessarily made a plan file. A subsequent bounded one-file Claude edit also succeeded; one earlier Claude max-turn failure and the diagnostic remained. No usage receipt was available for either successful edit or the earlier Codex task attempts. These are operational usability signals, not matched task outcomes; overall effectiveness remains mixed and unproven. The two matched Codex task failures remain noncomparative, with orchestration/tool-interface misconfiguration signals; do not declare worker drift or attribute all failure to orchestration without task-specific evidence. The adapter environment marker is conditional on the exact adapter being installed on the host.

The Advisor Council was consulted twice; both receipts report `decision_changed: true`. Usage reported: first Sol 1,230 and Gemini 3,628 tokens; follow-up Sol 1,023 and Gemini 3,355. This records actual consultation and its effect on the verification steps, not independent acceptance.

Documentation checks must include local Markdown links and installation paths plus `git diff --check`; no behavioral test outside the scoped trials is implied. Future evidence should preserve matched fixtures, exact CLI route/model, acceptance, tool/read counts, actual usage, attempts, interventions and time. Do not compare output length alone as a measure of total cost, and avoid routinely expensive synthetic tool probes.
